## Python

| 项 | 选型理由 | 约束 |
| --- | --- | --- |
| **Python 3.12** | 3.12+ 性能显著提升（3.11/3.12 全局速度、新语法）；requires-python `>=3.12,<3.14` 留出 3.13 兼容空间 | 不得使用 3.11 及以下；部分 Torch 2.11 轮子对 3.14 尚未发布 |
| **uv workspace** | 替代 Poetry：单一 `uv.lock`、workspace 成员共享依赖树、cpu/gpu 分组互不冲突（`conflicts: [{group=cpu},{group=gpu}]`）、PyPI 镜像友好 | 不得裸 `pip install`；必须走 `uv sync --all-packages --group cpu\|gpu`；不得在成员 pyproject.toml 单独声明 torch（强依赖分组） |
| **FastAPI 0.142** | 自动 OpenAPI、Pydantic 双向兼容、Starlette 可插拔、社区生态成熟 | `multipart.enabled=true` 仅用于 app-ingest-worker 解析；gateway multipart **必须** false |
| **LangGraph 1.2 + LangChain 1.4** | 显式节点/边/状态编排，适合 RAG 多分支流程（query→retrieval→rerank→generation）；LangChain TextSplitters 提供标准分块原语 | 节点不可变；状态字段必须可 JSON 序列化；不得在节点内做 I/O 阻塞 |
| **BGE-M3（dense 1024 + sparse）** | BAAI 开源、中文效果 SOTA、embedding/重排一体、FlagEmbedding 官方支持 | 维度固定 1024；sparse 向量需经 `aipaas_common.normalize_sparse_vector` 归一化 |
| **BGE-Reranker-Large** | 中文重排 SOTA、可单独部署 | 仅开发全量链路调用；P0 chat 链路未直接调用 |
| **MinerU** | 金融/标准类文档 PDF 解析（表格、条款结构、OCR 预留）；离线部署 | 需 GPU 或模型目录；`MINERU_API_TOKEN` 未配置时走在线 API |
| **pymilvus[model] ≥ 3.0.2** | Milvus 官方 Python SDK，含向量模型依赖；随 torch 分组安装 | 必须与 torch 同组安装（否则 PyPI 索引冲突） |
| **modelscope ≥ 1.40** | 模型下载与管理（离线部署） | HuggingFace 镜像可选；离线模式设置 `HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1` |
| **DashScope / ragas** | 阿里云在线 LLM；ragas 用于评估 | 配置包 YAML 引用 `OPENAI_API_KEY` 或独立密钥 |
| **MCP v1 + mcp-agents1.0** | MCP 协议联网搜索扩展（P0 契约预留） | 暂未被 P0 主链路实际调用；v2（mcp-agents2.0）独立管理，暂未被依赖 |

## Java

| 项 | 选型理由 | 约束 |
| --- | --- | --- |
| **Java 21** | LTS 至 2031；虚拟线程适合高并发 I/O（gateway 流式转发）；语法糖（records/pattern matching） | `java.version=21`、`maven.compiler.release=21`；Dockerfile 用 `eclipse-temurin:21-jre` |
| **Spring Boot 3.4.1** | Spring Boot 3 LTS；虚拟线程自动配置；Observation API 与 Micrometer 统一可观测 | 不能与 Spring Boot 2.x 混用；`spring-boot-dependencies 3.4.1` 管理 |
| **Spring Boot Test** | JUnit 5 + MockMvc + MockBean；便于契约驱动测试 | 每个 Controller 单独测试；集成测试用 `@SpringBootTest(webEnvironment=MOCK)` |
| **Maven 多模块** | `pom.xml` 父 POM（modules: common, platform-gateway, platform-management）；统一 BOM 管理 | 子模块不得声明重复 dependencyManagement；公共依赖放 `libs/common` |
| **Flyway（classpath:db/migration/{common,postgresql}）** | SQL-only 迁移；V1~V9 覆盖 RBAC→知识库→导入→索引导建→导出→审计→请求日志；幂等执行 | 迁移脚本名 `V{n}__description.sql` 必须唯一；禁止事后修改已执行的脚本；Flyway baseline 可选（P0 不需要） |
| **Resilience4j 2.2** | `circuitbreaker pythonAi`（滑窗 20 / 失败率 50% / 打开 10s）；`ratelimiter p0Api`（100/s/实例）；`timelimiter pythonAi 5s` | 熔断只保护 Python 下游；Redis 限流器用 Redis 实现（若启用） |
| **JWT HS256** | 对称签名、性能好、Java + Python 共享密钥（通过 `platform-jwt-verify` 卷由 management 导出供 gateway 只读使用） | 密钥仅 management 持有；gateway **只读**挂载；密钥轮换通过 management 重新导出 + gateway 加载新版本 |
| **MinIO Java SDK 8.5.17** | AWS S3 协议；对象存储统一接入 | `minio.version=8.5.17`；bucket 自动创建 |

## 选型对比

### 为什么选 Milvus 而非 ES / Qdrant / Neo4j

| 维度 | Milvus 3.0 | Elasticsearch / OpenSearch | Qdrant | Neo4j（向量插件） |
| --- | --- | --- | --- | --- |
| 向量性能 | ⭐⭐⭐⭐⭐（自研 HNSW、GPU 加速可选） | ⭐⭐⭐（approximate 精度较差） | ⭐⭐⭐⭐⭐（Rust + HNSW） | ⭐⭐（向量为插件非核心） |
| dense+sparse 混合 | ✅ BGE-M3 原生 | ✅ BM25 插件 | ❌ 需另接 BM25 | ❌ |
| 生产成熟度 | ⭐⭐⭐⭐（国内大厂广泛用） | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐ |
| 生态成本 | 需 etcd + MinIO 依赖 | 单节点可用 | 单节点可用 | 图形数据库 |
| 适配场景 | **RAG 向量检索主力** | 全文搜索 + 向量辅助 | 纯向量 | 知识图谱 |
| **本项目选型理由** | RAG 场景向量为主；etcd/MinIO 依赖恰好与项目其它组件复用 | ES 全文是 P1 增强，当前不需要 | 性能好但生态不如 Milvus；且已有依赖 | 图数据库与 RAG 目标不匹配 |

### 为什么选 uv 而非 Poetry

| 维度 | uv | Poetry |
| --- | --- | --- |
| 速度 | ⭐⭐⭐⭐⭐（Rust 重写，比 pip 快 10–100×） | ⭐⭐ |
| workspace | ✅ 原生支持，单 lock | ❌ poetry-core 无 workspace；需 Poetry >= 1.7 实验 |
| 分组 | ✅ cpu/gpu 互斥分组，完美解决 torch + pymilvus[model] 强依赖 torch 问题 | ❌ groups 需 1.8+，互斥冲突难表达 |
| 索引控制 | ✅ 每个包指定 PyPI / PyTorch 官方索引 | ❌ 镜像和官方源混杂时易出问题 |
| lock 文件 | 单一 `uv.lock` 覆盖所有 workspace 成员 | 每个项目单独 `poetry.lock` |
| 脚本 | `uv run` / `uv sync` / `uv tree` | `poetry run` / `poetry install` |
| **本项目选型理由** | 多 workspace 成员 + torch 分组互斥 + PyPI 镜像与官方源共存 | Poetry 无法优雅处理这些约束 |

### 为什么 JWT HS256 替代 RS256

| 维度 | HS256（对称） | RS256 / ES256（非对称） |
| --- | --- | --- |
| 验签性能 | 极快（HMAC 对称） | 较慢（椭圆曲线 / RSA 公钥运算） |
| 密钥分发 | 对称密钥必须保密；gateway 只读挂载 volume | 公钥可公开分发 |
| 密钥管理复杂度 | 低（单密钥 + JWT 验证密钥卷导出） | 高（证书轮换、chain、JWKS 端点） |
| Python / Java 互通 | ✅ 同一字符串即可 | ✅ 但需证书格式协商 |
| 暴露面 | gateway 只读挂载 JWT 导出密钥，management 持有完整密钥环 | 公钥可下发但要防伪造 |
| **本项目选型理由** | 单平台内部服务（management→gateway）密钥分发通过内部命名卷，无公网交换；gateway 只读密钥卷最小化暴露面 | 非对称对本架构无收益 |

## 不使用清单（当前明确不使用）

| 项 | 原因 | 规划 |
| --- | --- | --- |
| **服务网格（Istio）** | 增加复杂度；当前 Compose + 单宿主机部署场景不需要 | 若迁移 K8s 再评估 |
| **Kubernetes** | 部署基线是 Compose 五级编排；Dockerfile + Compose 已覆盖开发/测试/生产 | k8s 目录有草稿但未启用 |
| **BM25 关键词召回** | P0 只做向量召回；HyDE + 语义改写覆盖 | P1 |
| **Cross-Encoder 重排** | svc-model-reranker 目前未在 P0 chat 链路调用 | P1（接入后替换或补充 Cosine 粗排） |
| **SSO / OAuth / OIDC / MFA** | 表结构预留 `sec_refresh_tokens`；目前只有 bcrypt 密码登录 | 生产环境需要 |
| **多租户管理界面** | 表结构已含 tenant_id（default 固定值）；无管理端点 | P1 规划 |
| **分布式全局限流** | Resilience4j `p0Api` 是单实例限流；跨实例需 Redis Limiter 实现 | 当前够用，后续扩展 |
| **OpenTelemetry Collector** | TraceId 贯穿链路但只在本地 Span 内存；Prometheus 指标已基本满足 | 后续接入 |
| **消息队列（RocketMQ 默认）** | profile: rocketmq 默认不启动；P0 用同步 HTTP + 异步任务状态机 | 异步任务量增大再评估 |
| **vLLM 本地推理（profile: vllm）** | 依赖 GPU；默认走在线 LLM API | 离线部署场景需要 |
| **GraphQL** | API 契约为 OpenAPI 3.1 + REST | — |
| **GraphQL / gRPC 主链路** | REST + HTTP JSON + SSE 已覆盖 | — |
| **微服务注册中心强依赖** | 用 Compose 服务名互相解析；Nacos 是可选 profile | profile: nacos |
| **KV 数据库（除 Redis 外）** | 已够用 | — |
| **分布式事务（2PC / Saga）** | P0 数据一致性用最终一致性 + 状态机 + 幂等键 | — |
