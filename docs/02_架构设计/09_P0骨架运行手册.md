# P0 骨架运行手册（Step 0）

> **历史记录**：本文记录 Step 0 冻结契约与骨架时的状态，其中部分端口映射、契约统计和“未实现”描述已随迭代变化。当前使用请以[快速使用入门](../01_入门指南/01_快速使用入门.md)、[架构说明](01_系统架构说明.md)和 [P0 部署手册](../03_运维验收/02_P0部署手册.md)为准。

> 目标：一条命令拉起 P0 骨架，验证各服务 `/healthz`、`/readyz` 返回 200，并完成一次「上传 → 问答」契约串联。
> 前置：Docker 24+、docker-compose v2.32+。本地开发另需 Python 3.12 / Node 20 / JDK 21（Java 可用容器构建，无需本机 JDK）。

---

## 1. 一键启动（compose）

```bash
cd /home/aipaas/aipaas
docker-compose -f deploy/docker/docker-compose-p0.yaml up -d --build
docker-compose -f deploy/docker/docker-compose-p0.yaml ps
```

首次启动需构建 platform-gateway / platform-management / app-ingest-worker / app-query-worker / mock / web 镜像并拉取 postgres、redis、minio、etcd、milvus、prometheus。Milvus 冷启动 `start_period` 90s，属正常现象。

### 端口与入口

| 组件 | 宿主端口 | 容器端口 | 用途 |
|---|---|---|---|
| platform-gateway（Java） | 仅容器内网 | 8080 | P0 契约主入口 `/api/v1/**`（统一入口网关） |
| platform-management（Java） | 仅容器内网 | 8080 | 管理服务（登录、RBAC、文档、审计落库） |
| contracts-mock | 4010 | 4010 | 零依赖契约 mock，前后端独立联调 |
| web（nginx） | 18080 | 80 | SPA + `/api/` 反代到 platform-gateway |
| postgres | 仅容器内网 | 5432 | 元数据/审计（不暴露宿主机） |
| redis | 56379 | 6379 | 缓存/幂等键 |
| minio | 19000 / 19001 | 9000 / 9001 | 对象存储 / 控制台 |
| milvus | 29530 / 29091 | 19530 / 9091 | 向量库 / 健康检查 |
| prometheus | 19090 | 9090 | 指标抓取（#177） |

> 端口刻意避开宿主机既有服务（8080/5432/6379/9000/19530/9091），可与现有 `deploy/docker/docker-compose.yaml` 并存。

## 2. 健康检查验证

```bash
B=http://127.0.0.1
for u in \
  "$B:8100/healthz" "$B:8100/readyz" \
  "$B:4010/healthz" "$B:4010/readyz" \
  "$B:18080/healthz" "$B:18080/readyz" \
  "$B:19090/-/healthy" "$B:29091/healthz" \
  "$B:19000/minio/health/live"; do
  printf '%-46s %s\n' "$u" "$(curl -s -o /dev/null -w '%{http_code}' "$u")"
done

# Java 服务默认不映射宿主机端口，进入容器内检查
docker-compose -f deploy/docker/docker-compose-p0.yaml exec p0-platform-gateway \
  wget -qO- http://127.0.0.1:8080/healthz
docker-compose -f deploy/docker/docker-compose-p0.yaml exec p0-platform-management \
  wget -qO- http://127.0.0.1:8080/healthz
```

期望全部为 `200`。基础设施容器状态：

```bash
docker-compose -f deploy/docker/docker-compose-p0.yaml ps --format 'table {{.Name}}\t{{.Status}}'
```

| 服务 | 检查方式 |
|---|---|
| postgres | `pg_isready -U aipaas -d aipaas` |
| redis | `redis-cli ping` → `PONG` |
| minio | `GET /minio/health/live` → 200 |
| etcd | `etcdctl endpoint health` |
| milvus | `GET :9091/healthz` → 200 |
| prometheus | `GET :9090/-/healthy` → 200 |
| platform-gateway | `GET :8080/healthz`、`/readyz` → 200 |
| platform-management | `GET :8080/healthz`、`/readyz` → 200 |

## 4. 「上传 → 问答」契约串联

### 4.1 对 mock（推荐，零依赖）

```bash
# 容器：http://127.0.0.1:4010
python3 aipaas-contracts/mock/smoke_upload_qa.py --base-url http://127.0.0.1:4010

# 或本地直跑
python3 aipaas-contracts/mock/server.py --port 4010
python3 aipaas-contracts/mock/smoke_upload_qa.py --base-url http://127.0.0.1:4010
```

期望 `23 passed, 0 failed`，链路：

```
/healthz → /readyz → POST /auth/login → POST /knowledge-bases
→ POST /knowledge-bases/{kbId}/documents（Idempotency-Key）
→ GET /ingest/tasks/{taskId}（轮询 QUEUED→RUNNING→SUCCEEDED）
→ GET /documents/{documentId}/chunks
→ POST /chat（引用 citation）
→ POST /chat/stream（meta/delta/done）
→ viewer 越权 403（PERM.*）
→ GET /audit-logs（doc.upload / chat.query / permission.denied）
```

### 4.2 对 platform-gateway（经 web 反代）

```bash
curl -s -X POST http://127.0.0.1:18080/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"admin12345"}'
```

> 以下 501 兜底描述属于 Step 0 骨架阶段的历史结论。当前 `platform-gateway` 会把管理请求代理到 `platform-management`，问答请求按 `AIPAAS_CHAT_SERVICE_URL` 直接调用 Python 服务；P0 编排中该地址指向仍是骨架的 `app-query-worker:8002`。

```bash
curl -s http://127.0.0.1:18080/api/v1/system/info -H 'Authorization: Bearer dev'
```

## 5. 本地开发（不启动容器）

### 5.1 mock（前端联调）

```bash
python3 aipaas-contracts/mock/server.py --port 4010
cd web && VITE_PLATFORM_API_BASE=http://127.0.0.1:4010/api/v1 npm run dev
# 或保留相对路径 /api/v1，让 vite 代理到 mock：
PLATFORM_API_TARGET=http://127.0.0.1:4010 npm run dev
```

### 5.2 Python

`app-ingest-worker` / `app-query-worker` 均为 uv workspace 成员，本地运行通过 `uv run --app <worker>` 启动（入口与端口见各 worker 的 `pyproject.toml`），依赖与运行方式详见 `pymodules/README.md`。容器内健康检查：

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8001/health   # app-ingest-worker 200
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8002/health   # app-query-worker 200
```

### 5.3 Java

```bash
# 本机有 JDK 21：
export JAVA_HOME=/path/to/jdk-21
cd javaplat && ./mvnw -q -DskipTests package
java -jar apps/platform-management/target/platform-management.jar
java -jar apps/platform-gateway/target/platform-gateway.jar

# 无本机 JDK：直接用容器构建/运行（构建上下文为 javaplat/）
docker build -f apps/platform-gateway/Dockerfile -t aipaas/platform-gateway:p0 .
docker build -f apps/platform-management/Dockerfile -t aipaas/platform-management:p0 .
docker run --rm -p 8081:8080 aipaas/platform-gateway:p0
```

### 5.4 Web 生产构建

```bash
cd web && npm ci && npm run build
```

## 7. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `p0-milvus` 反复重启 | etcd/minio 未就绪 | 等待 etcd/minio healthy；Milvus 冷启动约 90s |
| `p0-platform-gateway` 健康检查失败 | 镜像构建期 Maven 依赖未下载完 | `docker-compose build p0-platform-gateway` 查看日志；`docker logs p0-platform-gateway` |
| 端口被占用 | 宿主机已有服务 | 修改 compose 左侧端口（如 18081→18082），或先停旧容器 |
| web 502 `/api/` | platform-gateway 未就绪 | 等待其 healthcheck 通过；检查 `PLATFORM_API_UPSTREAM` |
| mock SSE 立即结束 | 客户端使用 HTTP/1.0 或代理缓冲 | mock 已用 `Connection: close`；nginx 已 `proxy_buffering off` |
| `verify_contract.py` 报坏引用 | 手工编辑 YAML 产生 `#components/...` | 必须写 `#/components/...` |
| Java 构建报 `release version 21 not supported` | 本机只有 JRE | 使用容器构建（见 5.3） |
