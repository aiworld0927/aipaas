# 08 模块说明文档

> 适用范围：当前 `aipaas` 仓库（Java 控制面 + Python 能力面 + React 前端 + OpenAPI 契约）。
> 本文回答三件事：**有哪些模块、各自负责什么、每个模块怎么启动**。
> 环境准备细节见 [02a 总体部署手册](04_总体部署手册.md)、[02b Web 模块](05_web模块开发部署.md)、[02c Python 模块](06_python模块开发部署.md)、[02d Java 模块](07_java模块开发部署.md)；架构决策与边界见 [03 架构说明](../02_架构设计/01_系统架构说明.md)。

## 1. 升级背景：从「Python 单体」到「Java + Python 双栈」

早期版本由 Python 一侧同时承担平台能力和 AI 能力，接口、权限、审计与解析、检索、生成混在一起。当前形态按**职责**拆成两层：

| 层 | 技术栈 | 承担的职责 | 不承担的职责 |
| --- | --- | --- | --- |
| 控制面（平台层） | Java 21 / Spring Boot 3 | 统一 `/api/v1` 入口、认证与 RBAC、文档与任务管理、审计与请求留痕、内容安全、导出、Trace 与指标 | 不做文档解析、不做向量检索、不直连大模型 |
| 能力面（AI 层） | Python 3.12 / FastAPI | 文档解析与分块、嵌入、重排、检索、生成、拒答、SSE 流式输出 | 不对外暴露平台鉴权入口（由 Java 侧统一收口） |
| 交互层 | React 18 / Vite / Nginx | 对话、导入、知识库、导出、个人中心 | 不直接持有业务密钥 |
| 契约层 | OpenAPI 3.1 | 跨端唯一权威契约、Mock、版本兼容 | 不承载运行时代码 |

统一调用链路（P0 与开发全量一致）：

```
  web ──/api/v1/**──> platform-gateway(Java, 8080) ──> platform-management(Java, 8080) ──导入──> app-ingest-worker(Python, 8001)
                                   └──问答──> app-query-worker(Python, 8002)
                                        （svc-model-embedding(8003) / svc-model-reranker(8004) + Milvus / MinIO / MongoDB 支撑）
```

> `platform-gateway` 的对话能力通过 `AIPAAS_CHAT_SERVICE_URL`（默认 `http://app-query-worker:8002`）下沉给 Python 查询服务，Java 侧只做验签、安全编排、审计与透传；管理请求代理到 `platform-management`。

## 3. Java 模块

### 3.1 `javaplat/libs/common`

- **职责**：跨模块共享的 DTO、错误码、统一响应信封 `{code,message,data,traceId}`、通用工具。
- **启动方式**：无独立进程，被 `platform-gateway` 与 `platform-management` 以 Maven 依赖引入。

### 3.2 `javaplat/apps/platform-management`

| 项 | 内容 |
| --- | --- |
| 职责 | 管理服务：登录/刷新/注销、用户与 RBAC、知识库、文档、审计落库、内容策略、系统配置、导入任务；持有数据库、Flyway、MinIO 与完整密钥 |
| 入口类 | `com.aipaas.platform.api.PlatformManagementApplication` |
| 端口 | 8080（`server.port`）；Compose 中只 `expose`，不映射宿主机端口 |
| 健康检查 | `GET /healthz`（容器 healthcheck）、`/actuator/health`、`/actuator/prometheus` |
| 数据库 | PostgreSQL，Flyway 自动迁移（`classpath:db/migration/{common,postgresql}`） |
| 关键环境变量 | `AIPAAS_DB_URL`（默认 `jdbc:postgresql://postgres:5432/aipaas`）、`AIPAAS_DB_USERNAME`/`AIPAAS_DB_PASSWORD`、`AIPAAS_BOOTSTRAP_ADMIN_PASSWORD`、`AIPAAS_STORAGE_TYPE`（默认 `minio`）、`AIPAAS_MINIO_ENDPOINT`/`AIPAAS_MINIO_ACCESS_KEY`/`AIPAAS_MINIO_SECRET_KEY`、`AIPAAS_KEYRING_PATH`、`AIPAAS_JWT_VERIFY_EXPORT_PATH`（默认 `/var/lib/aipaas/jwt-verify/jwt-secret`）、`AIPAAS_PARSE_SERVICE_URL`、`REDIS_HOST`/`REDIS_PORT`、`AIPAAS_ENV`、`AIPAAS_API_VERSION` |

**本地启动**（需先有一个可连的 PostgreSQL）：

```bash
cd javaplat
./mvnw -pl apps/platform-management -am spring-boot:run
# 数据库不在默认地址时显式传入：
AIPAAS_DB_URL=jdbc:postgresql://127.0.0.1:5432/aipaas \
AIPAAS_DB_USERNAME=aipaas AIPAAS_DB_PASSWORD=aipaas_p0 \
./mvnw -pl apps/platform-management -am spring-boot:run
```

**构建与测试**：

```bash
cd javaplat
./mvnw -pl apps/platform-management -am test                     # 单元测试（91 个）
./mvnw -pl apps/platform-management -am -DskipTests package      # 产出 apps/platform-management/target/platform-management.jar
docker build -f apps/platform-management/Dockerfile -t aipaas/platform-management:latest .   # 构建上下文为 javaplat/
```

**容器启动**（P0 编排中的 `p0-platform-management`，端口仅内网暴露，由 gateway 代理）：

```bash
cd deploy/docker
docker compose -f docker-compose-p0.yaml up -d p0-platform-management
docker exec -it p0-platform-management wget -qO- http://127.0.0.1:8080/healthz
```

### 3.3 `javaplat/apps/platform-gateway`

| 项 | 内容 |
| --- | --- |
| 职责 | 统一入口网关：本地 HS256 验签 + Redis 用户安全快照与 JTI 撤销校验、外部身份头清理与可信身份头重建、`/api/v1/**` 管理请求流式代理、问答安全编排、审计事件发布、Trace/幂等/SSE |
| 入口类 | `com.aipaas.platform.gateway.PlatformGatewayApplication` |
| 端口 | 容器内 8080；宿主机默认 `PLATFORM_GATEWAY_PORT=8081` |
| 管理链路 | `frontend → platform-gateway → platform-management` |
| 问答链路 | `frontend → platform-gateway → app-query-worker`（`/api/v1/chat`、`/api/v1/chat/stream` 由网关直接调用） |
| 状态依赖 | Redis 键 `aipaas:gateway:auth:{userId}`、`aipaas:gateway:revoked:{jti}`、`aipaas:gateway:content-policies`、`aipaas:gateway:audit` |
| 密钥挂载 | 只读挂载卷 `platform-jwt-verify` 到 `/var/lib/aipaas/jwt-verify`，不挂载 AES/审计密钥或业务数据卷 |
| 关键环境变量 | `PLATFORM_MANAGEMENT_URL`（默认 `http://platform-management:8080`）、`AIPAAS_CHAT_SERVICE_URL`（默认 `http://app-query-worker:8002`）、`AIPAAS_JWT_VERIFY_SECRET_FILE`（默认 `/var/lib/aipaas/jwt-verify/jwt-secret`）、`REDIS_HOST`/`REDIS_PORT`、`AIPAAS_ENV`、`AIPAAS_API_VERSION` |


**构建与测试**：

```bash

./mvnw -pl apps/platform-gateway -am -DskipTests package         # 产出 apps/platform-gateway/target/platform-gateway.jar
docker build -f apps/platform-gateway/Dockerfile -t aipaas/platform-gateway:latest .   # 构建上下文为 javaplat/
```

**容器启动**（P0 编排中的 `p0-platform-gateway`）：

```bash
cd deploy/docker
docker compose -f docker-compose-p0.yaml up -d p0-platform-gateway
docker exec -it p0-platform-gateway wget -qO- http://127.0.0.1:8080/healthz
```

## 4. Python 模块（uv workspace）

### 4.1 workspace 约定

`pymodules/pyproject.toml` 是 workspace 根，所有成员共用**一份 `uv.lock`** 和**一个 `.venv`**。

```bash
cd pymodules
uv sync --all-packages --group cpu     # 纯 CPU 机器
uv sync --all-packages --group gpu     # 有 NVIDIA 显卡（CUDA 12.8）
```

- `cpu` / `gpu` 两组互斥（`tool.uv.conflicts`），一次只能选一组；不带 `--group` 不会安装 torch 栈，模型服务无法运行。
- 本地运行统一用 `uv run python -m <包名>.api.app`，配置由 `APP_ENV` + `CONFIG_DIR` 决定：

```bash
cd pymodules
export APP_ENV=devcompany              # 或 devhome
export CONFIG_DIR=$PWD/configs         # 指向 aipaas_config.*.yaml 所在目录
cp .env.example .env                   # 首次运行前填密钥
```

### 4.2 四个可独立部署的 worker

| 服务 | 入口 | 端口 | 核心依赖 | 本地启动 |
| --- | --- | --- | --- | --- |
| 文档导入 | `app_ingest_worker.api.app` | 8001 | LangGraph、MinIO、MongoDB、Milvus、嵌入/重排服务 | `uv run python -m app_ingest_worker.api.app` |
| 知识库查询 | `app_query_worker.api.app` | 8002 | LangGraph、DashScope/LLM、MCP、Milvus、重排 | `uv run python -m app_query_worker.api.app` |
| 嵌入模型 | `model_embedding_worker.api.app` | 8003 | torch、transformers、BGE-M3（离线）或 DashScope（在线） | `uv run python -m model_embedding_worker.api.app` |
| 重排模型 | `model_reranker_worker.api.app` | 8004 | torch、transformers、bge-reranker-large（离线）或 DashScope TextReRank（在线） | `uv run python -m model_reranker_worker.api.app` |

补充说明：

- 端口默认值在 `pymodules/configs/aipaas_config.base.yaml`，可用 `APP_INGEST_WORKER_PORT` / `APP_QUERY_WORKER_PORT` / `MODEL_EMBEDDING_WORKER_PORT` / `MODEL_RERANKER_WORKER_PORT` 覆盖。
- 模型服务后端由 `EMBEDDING_BACKEND` / `RERANKER_BACKEND` 控制：`offline` 读取 `MODEL_BASE_DIR` 下的本地模型，`online` 走 DashScope 兼容接口（需要相应 API Key）。
- 每个模块的细节文档：`pymodules/docs/{app-ingest-worker,app-query-worker,model-embedding-worker,model-reranker-worker}.md`。
- 容器内启动命令见各自 `Dockerfile` 的 `CMD`（`.venv/bin/python -m <包名>.api.app`）。

### 4.3 共享包（`pymodules/packages`）

| 包 | 职责 |
| --- | --- |
| `common` | 配置加载（OmegaConf + Pydantic）、日志、通用客户端与工具 |
| `pipeline` | 文档解析管线：可插拔解析器 + 统一中间结构 + 版本化产物 |
| `retrieval` | 检索层（Milvus 适配、RRF） |
| `generation` | 生成链路：LLM 调用、Prompt 组装、幻觉抑制、拒答、格式化 |
| `storage` | 存储层：MongoDB / MySQL / MinIO / Kubernetes 客户端 |
| `model-clients` | 模型服务 HTTP 客户端（LLM、嵌入、重排） |
| `nacos` | Nacos 服务注册/注销（供各 worker 共用） |
| `mcp-agents1.0` | MCP 接入层（`mcp>=1.19,<2` + `openai-agents<0.20`），app-query-worker 使用 |
| `mcp-agents2.0` | MCP 接入层（`mcp>=2`），**不在 workspace 内**，当前无成员依赖，独立管理 |

共享包无独立启动方式，随依赖它的 worker 一起加载。

### 4.4 `pymodules/apps/apis`（平台侧历史 API，暂不处理）

- 早期平台侧 FastAPI（部署、镜像、容器、任务管理），**无 `pyproject.toml`、未纳入 workspace**。
- 现状：内部导入路径为 `app.apis.*`，但仓库中不存在 `app` 包，**当前无法直接 import/启动**，按约定保留不处理（参见 [02 开发环境搭建](03_环境搭建.md) 的已知问题记录）。
- 历史文档中的启动方式为 `cd pymodules && python -m uvicorn app.apis.aipaas_main:app --port 8000`，仅作背景参考。

### 4.5 `pymodules/apps/eval-runner`（离线评测脚本）

- **职责**：基于 ragas 对 RAG 端到端评估（Faithfulness、Answer Relevancy、Context Precision/Recall、Answer Correctness）。
- 读取同目录 `qa.csv`，输出 `eval_result*.csv`；非服务、无端口。

```bash
cd pymodules/apps/eval-runner
python eval.py        # 建议在 pymodules 的 workspace 虚拟环境内执行（依赖 ragas/datasets 等）
```

### 4.6 验收脚本（`pymodules/scripts`）

```bash
cd pymodules
uv run python scripts/acceptance/e2e_p0.py        # P0 端到端
uv run python scripts/acceptance/golden_eval.py   # 黄金集评测
uv run pytest tests -q                            # 单测/配置测试
```

## 9. 启动顺序与自检

**开发全量栈**：中间件（base）→ 模型服务 → 业务服务 → 前端（compose 已用 `depends_on` + healthcheck 编排）。

```bash
curl -s localhost:8003/health    # 嵌入
curl -s localhost:8004/health    # 重排
curl -s localhost:8001/health    # 导入
curl -s localhost:8002/health    # 查询
curl -s localhost:8080/healthz   # Java 平台（本地直跑时）
curl -sI localhost               # 前端
```

**P0 栈**：

```bash
curl -s localhost:18080           # web
curl -s localhost:4010/healthz    # 契约 Mock
docker exec -it p0-platform-gateway wget -qO- http://127.0.0.1:8080/healthz
docker exec -it p0-platform-management wget -qO- http://127.0.0.1:8080/healthz
```

## 10. 已知边界（避免误判）

1. **链路已接通不等于生产就绪**：P0 与开发全量栈的问答/导入均已接通 `app-query-worker` / `app-ingest-worker`，但契约冻结、容器健康不等于真实模型生产链路已压测就绪。
2. **Web 登录已接入平台统一认证**：前端经 `/api/v1` 反代到 gateway，使用 Bearer Token 鉴权。
3. **`apps/apis` 无法启动**：无 `pyproject.toml`、缺少 `app` 包，按约定暂不处理。
4. **两套 Compose 不混用**：`docker-compose.yaml`（开发全量）与 `docker-compose-p0.yaml`（P0 交付）端口、服务名、数据卷均不同。
5. **`platform-gateway` 依赖 Python 查询服务**：`AIPAAS_CHAT_SERVICE_URL` 默认指向 `app-query-worker:8002`，P0 与开发全量编排均已内置该服务。
6. **模型服务镜像以基座镜像为 FROM**：先构建 `docker/base/Dockerfile` 产出 `aipaas/aipaas-torch-{cpu|gpu}-base:local`，再构建两个模型镜像（详见 [02a 部署手册](04_总体部署手册.md) 7.5 节）。
