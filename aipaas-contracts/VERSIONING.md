# API 版本与兼容策略（对齐 P1 NFR#31）

> 契约版本：`1.1.0-p0`
> 适用范围：`aipaas-openapi-v1.yaml` 及其实现（Java platform-gateway / platform-management、Python rag-ai-api、Web 客户端）

## 1. 版本号方案

`MAJOR.MINOR.PATCH-STAGE`，例如 `1.0.0-p0`、`1.1.0-p1`。

| 段 | 触发条件 | 影响 |
|---|---|---|
| MAJOR | URL 主版本变更（`/api/v1` → `/api/v2`） | 不兼容；新旧并行 ≥2 个迭代期 |
| MINOR | 新增接口 / 新增可选字段 / 新增枚举值 / 新增错误码 | 兼容；次版本号 +1 |
| PATCH | 文档修正、描述、示例、非行为性约束 | 兼容；不需要客户端动作 |
| STAGE | `p0/p1/...` 标识当前迭代期 | 仅标记，不参与语义比较 |

当前阶段：**P0 契约冻结**，版本 `1.1.0-p0`，`info.x-contract-status: frozen`。`1.1.0-p0` 为安全底座实现所需的兼容补充，未改变既有接口语义。

## 2. 兼容性定义

**兼容（可直接发布）**
- 新增可选请求字段（有默认值）或响应字段。
- 新增枚举值（客户端必须容忍未知值，见第 6 节）。
- 新增接口或新增可选查询参数。
- 放宽校验（如 `maxLength` 增大）。
- 修改描述、示例、文档、`x-*` 元数据。

**破坏性（必须走第 3 节流程）**
- 删除/重命名接口、字段、枚举值。
- 字段类型变更或必填性从「可选」变「必填」。
- 收紧校验（如 `maxLength` 减小、范围缩小）。
- 修改错误码语义或 HTTP 状态映射。
- 改变幂等语义、分页默认值、鉴权方式。
- 变更 SSE 事件名或 `data` 结构。

## 3. 破坏性变更告警流程（≥2 个次版本）

对齐 NFR#31：**破坏性变更须提前不少于 2 个次版本发布告警**。

以 `1.3.0` 计划移除 `GET /documents/{id}/metadata` 的 `confidence` 字段为例：

| 版本 | 服务端行为 | 响应头 |
|---|---|---|
| `1.3.0`（告警起点） | 字段仍返回；日志标记调用方 | `Deprecation: true`、`Sunset: Wed, 01 Apr 2026 00:00:00 GMT`、`Link: <https://docs/migration#metadata-confidence>; rel="deprecation"` |
| `1.4.0`（第二个告警版本） | 同上，仍未移除 | 同上 |
| `1.5.0`（允许移除） | 字段移除 | `Sunset` 已到期 |

要求：

1. 告警期内**新旧字段并存**，服务端不得提前移除。
2. `Deprecation`/`Sunset` 头必须出现在**所有**受影响响应中（含错误响应）。
3. `Sunset` 时间距首个告警版本发布时间 ≥ **2 个迭代期**（P0 迭代期以功能清单期次为准）。
4. 迁移说明写入 `docs/02_架构设计/08_P0_API契约评审.md` 的遗留项或独立迁移文档。

契约中的声明位置：

```yaml
info:
  x-compatibility-policy:
    breaking-change-notice-versions: 2
    deprecation-headers: [Deprecation, Sunset, Link]
```

## 4. URL 主版本策略

- 主版本体现在路径：`/api/v1`。
- 进入 `/api/v2` 时，`/api/v1` **至少保留 2 个迭代期**，期间双版本并行；网关/反代按路径前缀路由。
- 健康检查与 `/system/info` 不受主版本约束。

## 5. 字段演进规则

| 场景 | 做法 |
|---|---|
| 新增字段 | 必须可选并提供默认值；响应新增字段客户端应忽略未知字段 |
| 废弃字段 | 保留 ≥2 个次版本 + `Deprecation` 头；不得复用旧字段名表达新语义 |
| 预留字段（`x-reserved-for`） | P0 可空、不参与逻辑；启用时按 MINOR 升级，并在变更日志说明 |
| 枚举扩展 | 只增不删；客户端必须按「未知值降级」处理 |
| 错误码扩展 | 新增码必须落在既有分段（AUTH/PERM/PARAM/BIZ/SYS/RATE）内 |
| `tenantId` | 自 P0 起存在；P1 #131 启用时不改变字段名与类型 |

## 6. 客户端容忍规则（强制）

1. 忽略未知响应字段。
2. 未知枚举值按「未知」处理，不得抛异常或崩溃。
3. 以 `code` 判断业务结果，不以 HTTP 200/非 200 猜测。
4. SSE 忽略未知事件类型（保留 `ping` 心跳）。
5. 分页以响应 `total` 为准，不假设页数。
