#### 使用uv进行包管理

uv 提供了与 pip 完全兼容的命令接口，可以直接替换已有工作流中的 pip 命令：

安装包：

```
# 安装包
uv pip install requests                  # 安装最新版本
uv pip install requests==2.31.0          # 安装特定版本
uv pip install -r requirements.txt       # 从 requirements.txt 批量安装

# 升级/卸载/查看包
uv pip install --upgrade requests        # 升级包
uv pip uninstall requests                # 卸载包
uv pip list                              # 查看已安装的包

# 导出依赖
uv pip freeze > requirements.txt         # 导出当前环境依赖到 requirements.txt
```

在项目模式下，推荐使用 `uv add` 和 `uv remove` 管理依赖，它们会自动更新 `pyproject.toml` 和 `uv.lock`：

```
# 添加生产依赖
uv add requests

# 添加指定版本的依赖
uv add "requests>=2.31.0"

# 移除依赖
uv remove requests
```

**优先用 `uv add` 的场景（核心推荐）**

- 安装项目核心依赖（如loguru、langchain、FlagEmbedding、pymilvus等）：这类依赖是项目长期运行的基础，uv add会将其写入pyproject.toml，并生成uv.lock

  锁定版本，避免团队协作 / 部署时版本漂移。

- 安装开发依赖（如测试、格式化工具）：用uv add --dev xxx区分开发 / 生产依赖，生产环境同步时（uv sync --prod）自动剔除冗余依赖。

- 常规依赖安装（无特殊镜像 / 参数需求）：如numpy、pandas、fastapi等，通过uv add统一管理，契合项目

  pyproject.toml核心配置体系。

**仅用 `uv pip` 的场景（特殊需求）**

- 安装 PyTorch：

  需指定 CUDA 专属镜像源（--index-url https://download.pytorch.org/whl/cu124），

  uv pip支持自定义--index-url参数，适配这类特殊安装需求；

- 临时测试 / 调试依赖：

  比如临时装包验证功能，测试完无需保留依赖记录，避免污染pyproject.toml；

- 迁移旧requirements.txt依赖：若有历史requirements.txt，可先用uv pip install -r requirements.txt快速安装，再逐步迁移到uv add标准化管理。

# GPU / CPU 双机器：uv 依赖分组管理

一台有 NVIDIA 显卡、一台只有 CPU，两台机器共用同一份 `pymodules/pyproject.toml`
（以及同一份 `uv.lock`）。思路是：**通用依赖 + 两个互斥分组（gpu / cpu）**，
每台机器只同步自己那一组，同步完成后开发期间环境不再变动。

## 配置结构（pymodules/pyproject.toml）

| 配置项 | 作用 |
| --- | --- |
| `[project].dependencies` | 两台机器都要装的通用依赖 |
| `[dependency-groups].gpu` | `torch/torchvision/torchaudio==...+cu128` + `flagembedding` |
| `[dependency-groups].cpu` | `torch/torchvision/torchaudio==...+cpu` + `flagembedding` |
| `[tool.uv].conflicts` | 声明 `cpu` 与 `gpu` 互斥，`uv lock` 生成两套独立解析分支 |
| `[tool.uv.sources]` | 三个 torch 包按 `group` 分别指向 `pytorch-cpu` / `pytorch-cuda128` 索引 |
| `[[tool.uv.index]]` | 两个 PyTorch 官方索引都带 `explicit = true`，只服务显式指定的包 |

两个设计要点（改动时不要踩）：

1. **版本必须带本地版本号**：CPU 机器写 `==2.11.0+cpu`、GPU 机器写 `==2.11.0+cu128`。
   若只写 `==2.11.0`，按 PEP 440 它同时满足两种 wheel，uv 就分不清该装哪一个。
2. **`flagembedding` 必须放在分组里**：它（经 `accelerate` / `peft` / `sentence-transformers`）
   强依赖 `torch`。一旦留在通用依赖里，默认依赖树会额外解析出一个 PyPI 版 torch，
   `uv run` 时会把已经同步好的 CPU/GPU 版 torch 覆盖掉。

## 首次同步：每台机器执行一次

```bash
# 有 NVIDIA 显卡的机器（CUDA 12.8 构建）
uv sync --group gpu

# 只有 CPU 的机器（纯 CPU 构建，不带 nvidia-* 运行时包）
uv sync --group cpu
```

同步完成后检查版本和 GPU 是否可用：

```bash
uv run --no-sync python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
# GPU 机器期望：2.11.0+cu128 True
# CPU 机器期望：2.11.0+cpu  False
```

## 日常开发：程序运行

```bash
uv run python app/main.py          # 直接运行即可，不会动已同步的 torch
uv run pytest tests                # 测试同理
```

说明：`uv run` 只会补装缺失的包，**不会删除**已安装的分组包，所以同步好的
CPU/GPU 版 torch 在开发期间保持不变（这是"同步一次、长期不动"的关键）。

PyCharm 里把解释器指向 `pymodules/.venv`（uv 生成的虚拟环境）即可；
如果用 uv 运行配置，命令填 `uv run --no-sync ...` 更稳妥。

## 需要牢记的三条规则

```bash
# 1. 同步时一定要带 --group，裸 uv sync 会剔除分组里的 torch/flagembedding
uv sync --group gpu          # ✅
uv sync                      # ❌ 会把 torch 等分组包卸载掉

# 2. 不要同时选两组，uv 会直接报错（这是特性，防止装出混杂环境）
uv sync --group cpu --group gpu
# error: Groups `cpu` and `gpu` are incompatible with the conflicts

# 3. uv add / uv remove 不会剔除分组包，增删依赖后无需重新分组同步
uv add requests
```

## 同一台机器切换分组 / 升级版本

版本号不同（`+cpu` 与 `+cu128` 不同 wheel），uv 会自动卸载旧的重装新的：

```bash
uv sync --group cpu     # 从 GPU 切到 CPU
uv sync --group gpu     # 从 CPU 切回 GPU
```

修改了 `pyproject.toml` 中的分组或 torch 版本后，先重新锁定再同步：

```bash
uv lock                 # 重新生成全局 uv.lock（含 cpu、gpu 两套分支）
uv sync --group gpu     # 或 --group cpu
```

## 常见问题

- **`uv run` 后 torch 变成没有 `+cpu/+cu128` 后缀的版本**：说明通用依赖里混进了
  强依赖 torch 的包（例如把 `flagembedding` 写回 `[project].dependencies`）。
  把它放回 `cpu` / `gpu` 两个分组，重新 `uv lock` 即可。
- **`uv sync --group cpu` 报版本找不到**：确认 PyTorch 索引里存在该版本
  （`https://download.pytorch.org/whl/cpu`、`https://download.pytorch.org/whl/cu128`），
  版本号必须与索引里的本地版本号完全一致。
- **GPU 机器装成了 CPU 版**：检查是否误用了裸 `uv sync`，重新执行
  `uv sync --group gpu --reinstall-package torch torchvision torchaudio`。
