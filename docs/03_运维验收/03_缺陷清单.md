## D-01 向量库故障未降级为关键词检索

| 字段 | 内容 |
| --- | --- |
| 严重级别 | 中 |
| 发现人 | 测试与交付负责人 |
| 发现时间 | 2026-11-19 |
| 环境 | `pymodules` 离线验收（`load_test.py`） |
| 关联功能 | #70 向量召回、NFR #15 |
| 复现步骤 | 1. 构造 `FailingSearcher`（模拟 Milvus 不可用）；2. `RetrievalService.retrieve` 发起检索；3. 查看结果 |
| 预期 | 向量库故障时自动降级为关键词检索，仍返回可用结果 |
| 实际 | 返回 `degraded=true`、`degraded_reason=VECTOR_BACKEND_ERROR`、`hits=0`，warning `VECTOR_BACKEND_DEGRADED`，无关键词回退 |
| 影响 | P0 主链路可用（生成层会受控拒答，不产生幻觉）；检索完全不可用期间无法提供兜底结果 |
| 根因 | 检索服务仅实现向量通道；BM25 关键词检索在范围内属 P1 #71 |
| 处置 | 记录为受限通过；P1 引入 BM25/关键词索引并接入故障回退 |
| 责任人 | 检索组 |
| 修复计划 | 1）新增关键词索引构建与查询；2）`RetrievalService` 在向量异常时调用关键词检索并标注 `degraded_reason=KEYWORD_FALLBACK`；3）补充故障注入测试 |
| 复测时间 | 2026-12-15 |
| 证据 | `docs/03_运维验收/06_性能压测/load_test_snapshot.json` → `degradation.vectorStoreFailure` |

## D-02 入口全局限流未在服务内实现

| 字段 | 内容 |
| --- | --- |
| 严重级别 | 中 |
| 发现人 | 测试与交付负责人 |
| 发现时间 | 2026-11-19 |
| 环境 | `pymodules` 离线验收（`load_test.py`） |
| 关联功能 | #177 指标监控、NFR #16 |
| 复现步骤 | 1. 验证 LLM 出站熔断：连续 5 次故障；2. 验证滑动窗口工具：20/秒上限下发起 26 次；3. 检查服务入口是否有全局限流中间件 |
| 预期 | 服务入口按租户/用户维度限流，超限返回 429 `RATE.*` |
| 实际 | LLM 出站熔断与工具级滑动窗口生效；服务入口无全局限流中间件，依赖反向代理/网关 |
| 影响 | 单实例可被突发流量压满；不影响功能正确性 |
| 根因 | P0 约定由反向代理 + 网关承担入口限流，服务内仅做最小熔断 |
| 处置 | 记录为受限通过；P1 网关统一限流或服务内 Resilience4j |
| 责任人 | 平台架构组 |
| 修复计划 | 1）网关配置按租户/IP 的 QPS 限额；2）429 + `Retry-After`；3）压测验证限流阈值与告警 |
| 复测时间 | 2026-12-20 |
| 证据 | `docs/03_运维验收/06_性能压测/load_test_snapshot.json` → `degradation.rateLimit` |

| 证据 | `docs/03_运维验收/05_端到端测试/E2E-RESULT.json` 步骤 2；PARSE-REPORT §3 |

## D-04 `web/dist` 属主异常导致默认构建失败

| 字段 | 内容 |
| --- | --- |
| 严重级别 | 低 |
| 关联功能 | #242/#246 前端 |
| 现象 | `npm run build` 清理 `web/dist/assets` 时报 `EACCES` |
| 原因 | 历史容器构建产物属主为 root，当前用户无删除权限 |
| 规避 | 使用 `npx vite build --outDir dist-acceptance --emptyOutDir` 构建成功（51 modules，产物 257.16 kB） |
| 影响 | 仅影响本地默认构建目录，不影响源码与交付 |
| 责任人 | 前端组 |
| 修复计划 | CI 固定构建用户与目录权限；本地清理 root 属主产物 |
| 复测时间 | 2026-11-25 |
| 证据 | 构建日志（51 modules transformed，`built in 498ms`） |
