# 企业级 RAG 分层架构：功能与数据明细

下面按 **Python RAG 核心层** 和 **Java 在线高并发服务层** 两层分别展开。先给一张全局图，再逐层列明细。

------

## 全局架构图

```python
┌──────────────────────────────────────────────────────────────┐
│                      客户端 / 上层业务                         │
└───────────────────────────┬──────────────────────────────────┘
                            │ HTTPS
┌───────────────────────────▼──────────────────────────────────┐
```

# 一、Python RAG 核心层

Python 层承担 **"RAG 全生命周期"**：从文档进入系统，到回答用户问题。可细分为三个子模块。

------

## 1.1 离线导入模块（Import Pipeline）

### 功能明细

| 序号 | 功能             | 说明                                                         |
| :--- | :--------------- | :----------------------------------------------------------- |
| 1    | 文档接入         | 从对象存储/MQ/API 拉取 PDF、Word、Markdown、HTML、Excel、图片 |
| 2    | 格式解析         | PDF→Markdown、OCR 识别扫描件、表格结构化提取                 |
| 3    | 图片处理         | 提取图片、修复相对路径、图片 OCR/多模态描述、上传对象存储    |
| 4    | 文档清洗         | 去页眉页脚、去水印、去重复段落、格式归一                     |
| 5    | 文档分块         | 语义分块 / 固定窗口 / 层级分块（父子块）、重叠控制           |
| 6    | 元数据抽取       | 标题、作者、部门、生效日期、密级、业务标签                   |
| 7    | 条目/实体识别    | 产品名、条款号、法规编号、人名、机构名等结构化抽取           |
| 8    | 向量化 Embedding | 调用 BGE/M3E/text-embedding，批量生成向量                    |
| 9    | 稀疏向量生成     | BM25 / SPLADE 稀疏向量，用于混合检索                         |
| 10   | 知识图谱构建     | 三元组抽取、实体对齐、写入 Neo4j                             |
| 11   | 索引写入         | 写入 Milvus（向量）、ES（全文）、Neo4j（图谱）               |
| 12   | 版本管理         | 文档版本、索引版本、增量/全量重建                            |
| 13   | 去重与冲突检测   | 相似 chunk 去重、同名实体消歧                                |
| 14   | 质量校验         | chunk 长度分布、空 chunk、embedding 维度校验                 |
| 15   | 流程编排         | LangGraph 状态图，节点失败重试、断点续跑                     |

### 涉及数据

**输入数据**

- 原始文件（PDF/DOCX/MD/HTML/图片）
- 文件元数据：文件名、大小、上传人、上传时间、来源系统
- 导入任务参数：知识库 ID、分块策略、embedding 模型、是否重建

**中间数据（LangGraph State）**

- `import_file_path`：文件路径
- `markdown_content`：解析后的 MD
- `image_list`：提取的图片及路径
- `chunk_list`：分块结果
- `chunk_metadata`：每个 chunk 的元信息
- `embedding_batch`：向量批次
- `entity_list` / `triple_list`：图谱数据
- `task_id` / `trace_id`：追踪标识
- `error_info`：节点错误

**输出数据（写入存储）**

- 向量集合：`chunk_id`、`vector`、`sparse_vector`、`metadata`
- 全文索引：chunk 原文、标题、标签
- 图谱：节点（实体）、边（关系）、属性
- MySQL：文档表、chunk 表、任务表、版本表
- 对象存储：原文件、图片、解析产物

## 1.2 在线检索模块（Retrieval Pipeline）

### 功能明细

| 序号 | 功能        | 说明                                       |
| :--- | :---------- | :----------------------------------------- |
| 1    | Query 理解  | 意图分类、实体识别、查询改写、多轮指代消解 |
| 2    | Query 扩展  | 同义词、HyDE、多查询生成（Multi-Query）    |
| 3    | 向量检索    | 稠密向量 top-k 召回（Milvus）              |
| 4    | 稀疏检索    | BM25 / SPLADE 召回（ES）                   |
| 5    | 混合检索    | 稠密+稀疏融合（RRF、加权）                 |
| 6    | 图谱检索    | 实体链接 + 子图召回（Neo4j）               |
| 7    | 元数据过滤  | 按部门、密级、时间、业务标签过滤           |
| 8    | 权限过滤    | 按用户角色/组织过滤可见 chunk              |
| 9    | Rerank 重排 | BGE-Reranker / Cohere Rerank 精排          |
| 10   | 去重与合并  | 相似 chunk 合并、相邻 chunk 拼接           |
| 11   | 上下文压缩  | 长上下文裁剪、LLM 压缩                     |
| 12   | 引用溯源    | 保留 chunk → 文档 → 页码的溯源链           |
| 13   | 缓存        | 查询缓存、embedding 缓存、结果缓存         |
| 14   | 编排        | LangGraph 编排多路召回 → 融合 → 重排       |

### 涉及数据

**输入数据**

- 用户 query 原文
- 会话上下文（多轮）
- 用户身份、角色、组织、权限
- 检索参数：top_k、阈值、过滤条件、知识库 ID

**中间数据**

- `rewritten_query`：改写后的查询
- `query_vector` / `sparse_vector`：查询向量
- `dense_candidates`：稠密召回结果
- `sparse_candidates`：稀疏召回结果
- `graph_candidates`：图谱召回结果
- `fused_candidates`：融合后候选
- `reranked_candidates`：重排后结果
- `filtered_candidates`：权限/元数据过滤后
- `context_chunks`：最终上下文

**输出数据**

- 检索结果列表：`chunk_id`、`score`、`content`、`metadata`、`source`
- 溯源链：chunk → 文档 → 页码 → 段落
- 检索指标：召回耗时、各路召回量、rerank 耗时

## 1.3 在线生成模块（Generation / Orchestration）

### 功能明细

| 序号 | 功能        | 说明                                            |
| :--- | :---------- | :---------------------------------------------- |
| 1    | Prompt 组装 | 系统提示、上下文注入、few-shot、格式约束        |
| 2    | LLM 调用    | 多模型路由、流式输出、重试降级                  |
| 3    | 工具调用    | Function Calling、Agent 工具（检索、计算、API） |
| 4    | 多轮对话    | 会话状态管理、历史压缩                          |
| 5    | 答案生成    | 基于上下文的 grounded 回答                      |
| 6    | 引用标注    | 答案中标注 [1][2] 对应 chunk                    |
| 7    | 幻觉检测    | 答案与上下文一致性校验                          |
| 8    | 敏感词过滤  | 输出合规检查                                    |
| 9    | 流式返回    | SSE / WebSocket 流式 token                      |
| 10   | 编排        | LangGraph Agent 图：检索 → 生成 → 校验 → 修正   |

### 涉及数据

**输入数据**

- 检索结果上下文
- 用户 query + 会话历史
- Prompt 模板、模型参数（temperature、max_tokens）
- 工具定义、Agent 配置

**中间数据**

- `prompt_messages`：完整 prompt
- `llm_response`：模型原始输出
- `tool_calls`：工具调用记录
- `citations`：引用映射
- `hallucination_score`：幻觉分

**输出数据**

- 最终答案文本
- 引用列表
- token 用量、耗时、模型名
- 会话记录（写入 MySQL/Redis）

# 四、两层交互的数据契约（关键）

两层之间必须定义清晰契约，否则会耦合。

**Java → Python 检索请求**

```
{
  "trace_id": "xxx",
  "tenant_id": "t1",
  "user_id": "u1",
  "query": "产品安全手册里的注意事项",
  "kb_ids": ["kb1", "kb2"],
  "filters": {
    "dept": ["研发"],
    "security_level": ["public", "internal"],
    "time_range": ["2024-01-01", "2024-12-31"]
  },
  "top_k": 20,
  "rerank": true,
  "stream": true
}
```

**Python → Java 检索响应**

```
{
  "trace_id": "xxx",
  "chunks": [
    {
      "chunk_id": "c1",
      "content": "...",
      "score": 0.92,
      "metadata": {"doc_id": "d1", "page": 12, "dept": "研发"},
      "source": {"doc_name": "手册.pdf", "url": "..."}
    }
  ],
  "answer": "根据手册...",
  "citations": [{"index": 1, "chunk_id": "c1"}],
  "usage": {"prompt_tokens": 1200, "completion_tokens": 300},
  "latency_ms": 850
}
```

# 五、一句话总结

> **Python 层管"AI 与数据"**：导入、解析、分块、向量化、图谱、检索、重排、LLM 生成与编排，涉及原始文档、chunk、向量、图谱、会话上下文等。
> **Java 层管"服务与治理"**：接入、鉴权、限流、会话、权限、模型路由、任务调度、审计、可观测，涉及用户、权限、知识库元数据、任务、配额、审计等。
> **两层通过明确的数据契约（trace_id、filters、chunks、usage）交互**，Python 不做高并发治理，Java 不碰 AI 算法，各司其职。
