## 2. 调用链路与边界

```
浏览器 ──HTTPS 443──> web/nginx ──/api/v1/**──> platform-gateway(宿主 8081)
                                        │  ManagementProxyController 通用反代
                                        ├──────────────> platform-management(容器 8080)
                                        │                auth / conversation / tenant / rbac / admin / document
                                        └─/chat、/chat/stream─> app-query-worker:8002（问答链路不变）
```

- 新增 `/api/v1/*` 端点**无需修改网关路由**：`ManagementProxyController` 使用 `@RequestMapping("/api/v1/**")` 通用反代；仅 SSE（`Content-Type: text/event-stream`）走 `StreamingResponseBody`，普通 JSON 同步 `byte[]` 返回（修复过网关偶发 200 空响应体问题）。
- 注册接口需在**三处白名单**同步放行，缺一即 401：
  - management `api/SecurityConfig.java`：`/api/v1/auth/login`、`/auth/refresh`、`/auth/register` permitAll；
  - gateway `GatewaySecurityConfig.java`；
  - gateway `GatewayJwtAuthenticationFilter.java`。
- management 启动类 `PlatformManagementApplication.scanBasePackages` 必须包含 `com.aipaas.platform.conversation`、`com.aipaas.platform.tenant`，否则新包端点返回 501 NOT_IMPLEMENTED（本次实际踩过）。

> **契约差距**：`aipaas-contracts/openapi/aipaas-openapi-v1.yaml`（1.1.0-p0）尚未收录本批端点（`/auth/register`、`/conversations/**`、`/admin/tenants/**`、`/documents/{id}/grants` 等），见"后续事项"。

## 3. 数据库（Flyway V10）

事实源：`javaplat/apps/platform-management/src/main/resources/db/migration/common/V10__tenants_conversations_document_grants.sql`。V1–V9 未做任何修改。

| 表 | 关键字段 | 约束/索引 | 用途 |
| --- | --- | --- | --- |
| `tenants` | id(PK)、name、status(ACTIVE/DISABLED)、description | 种子数据 `default` 租户 | 租户台账 |
| `conversations` | id(PK)、tenant_id、user_id、title、deleted_at | `idx_conversations_user(tenant_id, user_id, updated_at desc)` | 会话（软删除） |
| `conversation_messages` | id(PK)、tenant_id、conversation_id(FK)、user_id、role、content、citations_json | `idx_conversation_messages(conversation_id, created_at)` | 消息持久化 |
| `document_grants` | id(PK)、tenant_id、document_id、subject_type(USER/ROLE)、subject_id、permission(READ/WRITE)、granted_by | 唯一键 `(tenant_id, document_id, subject_type, subject_id, permission)`；`idx_document_grants_doc` | 文档级 ACL |

隔离与初始化规则：

- 会话/消息/文档授权的所有 SQL 均强制带 `tenant_id`；会话再叠加 `user_id`，跨用户访问返回 404。
- 会话删除为软删除（`deleted_at`），清空消息为物理删除并 `touch` 会话更新时间。
- 创建租户时（`tenant/TenantRepository.provision`）自动：复制 default 租户权限目录 → 建默认知识库 `kb_<tenantId>` → 建 4 个内置角色（`rol_<tenantId>_<code小写>`）→ 复制角色权限与 KB 授权。
- 用户表 `sec_users`、角色表 `sec_roles` 等沿用 V1 的 `tenant_id` 字段，本轮补齐了管理端点与强制过滤。

## 4. 后端接口清单（增量）

统一前缀 `/api/v1`，统一信封 `{code,message,data,traceId}`；写请求需 `Idempotency-Key`。

### 4.1 认证与个人中心（auth）

| 方法/路径 | 权限 | 说明 |
| --- | --- | --- |
| POST `/auth/register` | 公开（白名单） | 开放注册即用：默认 `default` 租户 + `KB_UPLOADER` 角色；可指定 tenantId；201 |
| POST `/auth/login` | 公开 | 凭证校验后追加**租户停用校验**（403） |
| POST `/auth/refresh` / `/auth/logout` | 公开 / 登录 | 刷新轮换、注销撤销 |
| GET/PATCH `/auth/me` | 登录 | 当前用户（含租户、角色、权限）；改资料 |
| POST `/auth/password` | 登录 | 改密（校验旧密码，`auth_version+1` 使旧令牌失效） |

密码策略：12–128 位、不得包含用户名、不得为常见弱口令（`PasswordPolicy` 统一校验）。

### 4.2 会话（conversation，按当前用户隔离）

| 方法/路径 | 说明 |
| --- | --- |
| GET `/conversations?keyword=` | 列表/搜索（防抖由前端处理） |
| POST `/conversations` | 新建（201） |
| PATCH `/conversations/{id}` | 重命名 |
| DELETE `/conversations/{id}` | 软删除 |
| GET `/conversations/{id}/messages` | 消息列表（含 total） |
| POST `/conversations/{id}/messages` | 追加消息（role/content/citations） |
| DELETE `/conversations/{id}/messages` | 清空历史，返回 `{conversationId, cleared}` |

### 4.3 多租户（tenant）

| 方法/路径 | 权限 | 说明 |
| --- | --- | --- |
| GET `/admin/tenants` | `tenant:read` | 台账列表（含 userCount） |
| POST `/admin/tenants` | `tenant:write` | 创建，id 正则 `[a-z][a-z0-9-]{1,31}`；自动初始化（见 §3） |
| PATCH `/admin/tenants/{id}` | `tenant:write` | 改名/描述/启停用；`default` 禁止停用 |

### 4.4 用户与角色（admin / rbac）

| 方法/路径 | 权限 | 增量点 |
| --- | --- | --- |
| GET `/admin/users?tenantId=` | `user:read` | 支持按租户筛选；跨租户需 `*` 或 `tenant:read` |
| POST `/admin/users` | `user:write` | 请求体新增 `tenantId`，可在指定租户建号（角色按目标租户解析） |
| PATCH `/admin/users/{id}` | `user:write` | 资料/状态/角色 |
| GET `/permissions` | `role:read` | 权限点目录 |
| GET `/roles?tenantId=` | `role:read` | 支持跨租户查询（需 `*` 或 `tenant:read`，否则 403） |
| POST `/roles` | `role:write` | 创建角色 + 权限矩阵 + KB grants |
| PUT `/roles/{roleId}/permissions` | `role:write` | 更新矩阵；`PLATFORM_ADMIN` 不可降权；变更即时生效并通知网关失效缓存 |

角色请求体必须同时含 `permissions` 与 `grants`（grant 结构 `{permission, scopeType:"KB", scopeId}`）。

### 4.5 文档级 ACL（document）

| 方法/路径 | 权限 | 说明 |
| --- | --- | --- |
| GET `/documents/{id}/grants` | `doc:read` | 查询 ACL |
| PUT `/documents/{id}/grants` | `doc:write` | 整体替换 ACL（用户/角色 + READ/WRITE） |
| GET `/documents` / `/documents/{id}` | `doc:read` | 列表过滤不可见文档；详情做 READ 校验 |
| DELETE `/documents/{id}` | `doc:delete` | 追加 WRITE 级 ACL 校验 |

**ACL 判定顺序**（`DocumentGrantService.canAccess`）：`*` 或 PLATFORM_ADMIN 或上传者放行 → 该文档无 ACL 记录时放行（沿用知识库级授权）→ 有记录时仅匹配 USER/ROLE 主体，READ 覆盖读、WRITE 覆盖写。

## 5. 安全与管控规则汇总

- **跨租户访问**：所有支持 `tenantId` 参数的端点统一走 `resolveTenant`——仅 `*` 或 `tenant:read` 可指定非本租户，其余 403。
- **租户停用管控**：停用后该租户用户登录 403、注册 403、管理员建用户 403；已签发令牌不主动踢出（依赖改密/撤销机制）。
- **注册**：开放注册无需审批；默认租户 `default` + `KB_UPLOADER`；目标租户被停用则拒绝。
- **权限模型**：`SecurityPrincipal.permissions` 中 `*` 表示超级权限；`@RequirePermission` 逐端点声明；角色权限变更下一请求即生效。
- **审计**：登录/刷新/注册/建用户等沿用 `auth.*` 审计事件落库。

## 6. 前端页面与路由（web）

| 路由 | 页面 | 关键交互 |
| --- | --- | --- |
| `/login` | Login | 登录 + "立即注册"入口 |
| `/register` | Register | 用户名/显示名/邮箱/密码/确认/租户，成功跳 `/chat` |
| `/chat`、`/chat/:sessionId` | Chat | 打开会话加载服务端消息；发送时自动建会话、首条消息改名；标题内联编辑；清空历史走服务端；流式偏好持久化 |
| `/user` | UserCenter | 资料修改、改密、租户/角色/注册时间展示、对话设置（localStorage `aipaas.prefs.stream`） |
| `/knowledge` | Knowledge | 文档行"权限"弹窗：用户/角色 + READ/WRITE，整体替换保存 |
| `/admin` | Admin | 五个 tab：概览 / 用户与权限（租户筛选、跨租户建号）/ 租户管理 / 角色授权 / 系统配置 |
| 侧边栏（AppLayout） | — | 服务端会话列表、220ms 防抖搜索、内联重命名、删除联动服务端；接口不可用时回退本地缓存 |

API 客户端统一在 `web/src/api/p0Client.js`，新增方法与本批端点一一对应。

## 7. 构建、部署与验证

构建与部署（与既有手册一致，本次实际执行）：

```bash
# 后端
cd javaplat && JAVA_HOME=/usr/local/jdk21 PATH=/usr/local/jdk21/bin:$PATH \
  ./mvnw -o -q -pl apps/platform-management -am -DskipTests package
docker cp apps/platform-management/target/platform-management.jar aipaas-platform-management:/app/app.jar
docker restart aipaas-platform-management

# 前端
cd web && npx vite build --outDir /tmp/aipaas-web-dist3
docker exec aipaas-frontend sh -c "rm -rf /usr/share/nginx/html/*"
docker cp /tmp/aipaas-web-dist3/. aipaas-frontend:/usr/share/nginx/html/
docker commit aipaas-frontend aipaas/frontend:latest
```
