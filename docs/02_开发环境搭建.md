# 前端工程

## 容器构建&启动

```bash
# 构建
cd frontend && docker build -t aipaas-frontend:v1.0 .

# 运行（本机开发机快速验证）
docker run -d --name aipaas-frontend \
    -p 80:80 \
    -e QUERY_API_UPSTREAM=http://aipaas.aiworld.com:8001 \
    -e IMPORT_API_UPSTREAM=http://aipaas.aiworld.com:8000 \
    aipaas-frontend:v1.0
    
    
## 关键设计

- 多阶段 ：build 阶段`node:20-alpine` 做`npm ci` +`vite build` ，runtime 阶段`nginx:alpine` 只拷`dist/` → 最终镜像 ~20MB（vs build 阶段的 ~500MB）
- 缓存友好 ：先 COPY`package.json + package-lock.json` 执行`npm ci` ，再 COPY 源码 → 改`src/**` 不会触发依赖重装
- 反代与 dev 对齐 ：nginx 的`/query-api` 和`/import-api` 两条反代路径 与`vite.config.js` 里 dev proxy 完全一致 ，切换到生产无需改前端代码
- 运行时注入后端地址 ：nginx.conf.template 用`${QUERY_API_UPSTREAM}` /`${IMPORT_API_UPSTREAM}` 占位，容器启动时`envsubst` 替换 → 构建时不需要知道后端在哪，运行时通过`-e` 或 docker-compose 传

## 与后端的对应关系
## 2.1 根据 vite.config.js  的 dev proxy 和后端 pymodules Dockerfile 配置：
#  2.2 前端路径 vite dev → 生产反代 → 说明:
/query-api/  http://127.0.0.1:8001 QUERY_API_UPSTREAM  查询服务 
/import-api/ http://127.0.0.1:8000 IMPORT_API_UPSTREAM 导入服务（pymodules 自己在这个端口）
```



## docker-compose中配置

```bash
frontend:
  image: aipaas-frontend:v1.0
  environment:
    QUERY_API_UPSTREAM: http://some-query-service:8001
    IMPORT_API_UPSTREAM: http://python-service:8000
  ports: ["80:80"]
  
# 注意 ：两个后端服务名和端口需要根据你实际的部署调整——`deploy/docker-compose.yml` 里`python-service` 挂在`8001` 端口，而 pymodules Dockerfile 的 uvicorn 在`8000` 端口，请确认你的`QUERY_API_UPSTREAM` /`IMPORT_API_UPSTREAM` 分别指向哪个。
```
