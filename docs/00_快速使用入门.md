# 快速使用入门

本文提供四条互不混淆的使用路径。第一次接触项目时，建议先用 **Mock 演示**理解界面与 API，再按目标选择 P0 容器部署、真实算法离线验收或开发全量环境。

> 重要：契约 Mock、P0 Compose、离线验收和开发全量环境的验证目标不同。容器健康不代表真实 LLM/Milvus 业务链路已完成验收，Mock 数据也不代表检索质量。

## 1. 选择使用路径

| 目标 | 路径 | 依赖 | 能得到什么 |
| --- | --- | --- | --- |
| 尽快浏览界面、串联上传与问答 API | [A. Mock 演示](#2-a-mock-演示推荐首次使用) | Python 3、Node.js 20 | 浏览 Web、独立执行契约上传→问答→审计冒烟 |
| 验证 P0 服务、数据组件与监控部署 | [B. P0 Compose](#3-b-p0-compose-部署) | Docker 24+、Compose v2 | 12 个服务、Web、平台 API、Milvus、监控看板 |
| 复现真实 Python 业务包的功能与质量证据 | [C. 离线验收](#4-c-真实算法链路离线验收) | Python 3.12、uv | PDF→条款→索引→引用问答→简介→导出及质量报告 |
| 启动既有混合检索、重排和模型服务 | [D. 开发全量环境](#5-d-开发全量环境) | Docker、模型文件/在线密钥 | ingest/query/embedding/reranker 开发链路 |

## 2. A. Mock 演示（推荐首次使用）

### 2.1 启动契约 Mock

在仓库根目录执行：

```bash
python3 aipaas-contracts/mock/server.py --port 4010
```

另开终端验证完整契约链路：

```bash
python3 aipaas-contracts/mock/smoke_upload_qa.py \
  --base-url http://127.0.0.1:4010
```

该脚本覆盖登录、创建知识库、幂等上传、任务轮询、分块、问答、SSE、越权拦截和审计。

### 2.2 启动 Web

保持 Mock 运行，另开终端：

```bash
cd web
npm ci
PLATFORM_API_TARGET=http://127.0.0.1:4010 npm run dev
```

访问 `http://localhost:5173`。当前登录页是演示模式，输入任意**非空**用户名和密码即可进入。

可查看：

- `/chat`：问答与引用界面；
- `/import`：文档导入界面；
- `/knowledge`：知识库与文档界面；
- `/exports`：导出任务界面。

> Mock 不执行真实 PDF 解析、向量检索或 LLM 推理。当前登录页只写入演示登录态，没有调用 P0 `/auth/login`，与 `p0Client` 使用的 Bearer Token 也未同步；因此这里验证的是“页面浏览 + 独立 API 冒烟”，未配置有效 P0 Token 时，浏览器内问答会返回 401。生产集成必须完成真实登录联调。

## 3. B. P0 Compose 部署

### 3.1 准备配置

最低要求：Docker Engine 24+、Docker Compose v2.20+、4 核 CPU、8 GB 内存、30 GB 可用磁盘。

```bash
cd deploy/docker
cp .env.example .env
```

编辑 `.env`，至少设置以下口令；不要用示例默认值部署到共享或生产环境：

| 变量 | 要求 |
| --- | --- |
| `P0_BOOTSTRAP_ADMIN_PASSWORD` | 首次启动必填；12–128 位，包含大小写字母、数字和特殊字符 |
| `P0_PG_PASSWORD` | PostgreSQL 强口令 |
| `P0_MINIO_PASSWORD` | MinIO 强口令 |
| `GRAFANA_ADMIN_PASSWORD` | Grafana 管理员强口令 |

### 3.2 校验并启动

```bash
docker compose -f docker-compose-p0.yaml config -q
docker compose -f docker-compose-p0.yaml up -d --build
docker compose -f docker-compose-p0.yaml ps
```

Milvus 冷启动有 90 秒健康检查宽限期。若只有 Compose v1，将 `docker compose` 替换为 `docker-compose`。

### 3.3 健康检查

在 `deploy/docker` 目录执行：

```bash
# Web 与 Prometheus
curl -fsS http://127.0.0.1:18080/healthz
curl -fsS http://127.0.0.1:19090/-/ready

# Java 与 Python 仅在容器内网暴露，不默认映射到宿主机
docker compose -f docker-compose-p0.yaml exec p0-platform-gateway \
  wget -qO- http://127.0.0.1:8080/healthz

docker compose -f docker-compose-p0.yaml exec p0-platform-management \
  wget -qO- http://127.0.0.1:8080/healthz

docker compose -f docker-compose-p0.yaml exec rag-ai-api \
  python -c "import urllib.request; print(urllib.request.urlopen('http://127.0.0.1:8100/healthz').read().decode())"
```

### 3.4 访问入口

| 入口 | 地址 | 默认说明 |
| --- | --- | --- |
| Web | `http://localhost:18080` | 当前仍为演示登录 |
| Web HTTPS | `https://localhost:18443` | 开发默认可生成自签证书，浏览器会提示不受信任 |
| 契约 Mock | `http://localhost:4010` | 仅用于联调 |
| Prometheus | `http://localhost:19090` | 检查 targets 与告警规则 |
| Grafana | `http://localhost:13000` | 账号来自 `.env` |
| Alertmanager | `http://localhost:19093` | 告警聚合与抑制 |
| MinIO 控制台 | `http://localhost:19001` | 账号来自 `.env` |

### 3.5 当前容器边界

- `p0-platform-gateway` 与 `p0-platform-management` 容器内端口都是 **8080**，不是 8081；`rag-ai-api` 是 **8100**。三者默认不映射宿主机。
- P0 Compose 中的 `rag-ai-api` 只实现健康检查、指标、系统信息和统一 501 骨架，并未实现真实问答路由。
- Java 问答下游需指向实现 `/api/v1/chat` 的 `query-worker`；解析下游需指向 `ingest-worker`，并正确设置 `AIPAAS_CHAT_SERVICE_URL`、`AIPAAS_PARSE_SERVICE_URL`。
- 因此，本路径用于部署、平台接口和监控验证；真实算法链路请继续执行下一节，完整容器业务串联需在上述下游接入后重新验收。

详细配置、TLS、备份与回滚见 [P0 部署手册](./acceptance/P0-DEPLOYMENT-MANUAL.md)。

## 4. C. 真实算法链路离线验收

该路径直接调用 `aipaas_pipeline`、`aipaas_retrieval` 和 `aipaas_generation`，用确定性替身保证无外部模型时也能复现。它不是 Mock API，但也不等于真实 LLM/Milvus 生产压测。

### 4.1 安装环境

```bash
cd pymodules
uv sync --all-packages --group cpu
```

NVIDIA GPU 环境可按 [Python 模块文档](../pymodules/README.md) 改用 `gpu` 分组；`cpu` 与 `gpu` 不能同时启用。

### 4.2 一键复现核心证据

```bash
# 生成 52 条 golden set 与 59 条测试条款语料
uv run python scripts/acceptance/build_golden.py

# PDF → 解析 → 条款分块 → 向量/索引 → 引用问答 → 简介 → 导出
uv run python scripts/acceptance/e2e_p0.py

# Recall / Hit / Faithfulness / Citation / 幻觉率 / 拒答
uv run python scripts/acceptance/golden_eval.py

# 性能、故障降级、熔断与限流
uv run python scripts/acceptance/load_test.py

# 注入、越权、审计与导出权限
uv run python scripts/acceptance/security_checks.py

# Python 全量回归
uv run pytest tests -q
```

证据输出到 `docs/acceptance/`：

- [端到端报告](./acceptance/e2e/E2E-REPORT.md)
- [质量门禁报告](./acceptance/quality/GOLDEN-EVAL-REPORT.md)
- [压测报告](./acceptance/perf/LOAD-TEST-REPORT.md)
- [安全报告](./acceptance/security/SECURITY-REPORT.md)

> 验收使用测试摘要语料和抽取式 Stub，不是金融标准原文，也不能替代真实模型效果复测。跨期依赖和受限项以 [P0 验收报告](./acceptance/P0-ACCEPTANCE-REPORT.md) 为准。

## 5. D. 开发全量环境

开发全量编排与 P0 Compose 是两套入口：

```bash
cd deploy/docker
cp .env.example .env
# 按本机情况修改模型目录、APP_ENV、TORCH_VARIANT、密钥与 profiles
docker compose config -q
docker compose up -d --build
docker compose ps
```

默认应用端口：

| 服务 | 端口 | 启动模块 |

| 文档导入 | 8001 | `ingest_worker.api.app` |

| Embedding | 8003 | `model_embedding_worker.api.app` |

## 6. 完整业务链路的使用顺序

在真实 Python 下游、模型和平台认证完成联调后，按以下顺序使用：

1. 创建知识库并确认当前账号拥有上传和问答权限。
2. 上传文本型 PDF、DOCX、Excel 或 Markdown；P0 扫描件 OCR 不支持。
3. 等待导入任务成功，检查解析条款数、分块数和索引状态。
4. 先输入完整标准编号，再询问具体条款号，缩小检索范围。
5. 检查答案引用是否包含标准号、条款号和可回溯 Chunk；无证据时应拒答。
6. 查看标准简介，确认缺失要素标为“未识别”。
7. 创建条款导出，下载时系统再次校验权限并写审计。
8. 通过 TraceID、请求日志、Grafana 和审计记录定位问题。

## 7. 常用检查与停止命令

```bash
# 契约完整性与 P0 功能覆盖
python3 aipaas-contracts/scripts/verify_contract.py

# Java 回归
cd javaplat && ./mvnw clean test

# Web 构建
cd web && npm ci && npm run build

# 停止 P0 容器，保留数据卷
cd deploy/docker && docker compose -f docker-compose-p0.yaml down

# 停止开发全量环境，保留数据
cd deploy/docker && docker compose down
```

`down -v` 会删除数据卷，只有确认不再需要数据时才可使用。

## 8. 常见问题

| 问题 | 处理方式 |
| --- | --- |
| `Set P0_BOOTSTRAP_ADMIN_PASSWORD` | 在 `deploy/docker/.env` 设置符合策略的管理员口令后重新启动 |
| 宿主机访问不到 8081/8100 | P0 Compose 默认不映射这两个服务；使用容器内检查或显式增加安全的端口映射 |
| Web 返回 502 | 检查 `platform-gateway` 健康状态、Nginx upstream 和容器网络 |
| 问答返回 501 | 当前指向 `rag-ai-api` 骨架；切换到真实 `query-worker` 并复测 |
| 上传后解析失败 | 检查 `AIPAAS_PARSE_SERVICE_URL`、`ingest-worker` 路由与原始文件格式 |
| 扫描件无法解析 | P0 无 OCR，应返回 `PARSE.PDF_SCANNED`；不要按文本 PDF 误判 |
| 看不到监控数据 | 检查 Prometheus targets、服务 `/metrics` 和容器时间同步 |
| 导出返回 403 | 检查 `export:create/read`、知识库归属和 `permission.denied` 审计 |
